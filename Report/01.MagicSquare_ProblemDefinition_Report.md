## 1. 개요

MagicSquare_xx는 **4×4 부분 마방진** 문제를 통해, 구현 전에 **무엇이 맞고 틀린지·무엇부터 확인해야 하는지**를 명문화하는 실습 프로젝트이다.

본 보고서는 Mom Test 인터뷰에서 도출한 **진짜 문제**를 출발점으로, 도메인 규칙·판정 순서·세션 3 산출물(Rule/Command/Test Loop)까지 연결한다.

## 2. 도메인 정의

### 2.1 Magic Square (마방진)

4×4 격자에 **1~16**을 **중복 없이** 배치하고, **10개 선**(행 4 + 열 4 + 대각선 2)의 합이 모두 **34**가 되도록 만든다.

| 항목 | 값 |
|------|-----|
| 격자 크기 | 4×4 (16셀) |
| 사용 숫자 | 1 ~ 16 (중복 없음) |
| 빈칸 표기 | `0` (정확히 **2개**) |
| Magic Constant | **34** (= (1+2+…+16) ÷ 4) |
| 검증 대상 | **10선** — 행 4, 열 4, 대각선 2 |

### 2.2 예시 격자

```
 16   3   2  13
  5  10  11   0
  9   6   0  12
  4  15  14   1
```

- 빈칸 2개 → 1~16 중 **누락된 숫자 2개**를 찾아 채운다.
- 출력(향후): `[r1, c1, n1, r2, c2, n2]` (좌표 1-index)

## 3. Mom Test 결과

### 3.1 페르소나

| 항목 | 내용 |
|------|------|
| **역할** | 4×4 부분 마방진을 손으로/코드로 다루는 학습자 |
| **상황** | 재미로 퀴즈처럼 풀거나, 코드로 구현·실험 |
| **목표** | 빈칸 2개를 채워 10선 합이 34가 되도록 완성 |

### 3.2 표면 문제 (잘못된 정의 — 솔루션 혼입)

> "4×4 마방진에서 빈칸 2개를 채우는 **프로그램**을 만든다."

### 3.3 진짜 문제 (한 문장)

> 손으로 풀 때는 여러 행·열(·대각선) 조건을 동시에 추적·판정하기 어렵고, 코드로 옮기면 입력·타입·문제 출제 오류 가능성까지 겹쳐 **무엇이 맞고 틀린지, 무엇부터 확인해야 하는지** 판단하기 전에 헷갈린다.

### 3.4 Mom Test 증거 3줄

1. "여러 행열의 합을 **적지 않고 외우고 있는 것이 헷갈렸**어."
2. "코드로 다룰 때에는 **여러 경우의 수를 고려**해보느라 **훨씬 헷갈렸**어."
3. "**변수 타입이 달라서 오류**가 난다거나, **문제가 잘못 출제될 수 있는 가능성**"

### 3.5 인터뷰 관찰 요약

| 구분 | 손으로 풀 때 | 코드로 다룰 때 |
|------|-------------|---------------|
| **불편** | 여러 행·열 합을 머릿속에 유지하기 어려움 | 경우의 수·타입·입력 유효성이 겹쳐 혼란 |
| **대응** | 종이에 작게 적음 | *(구체적 대응 미기록)* |
| **소요** | 1분 이내 | *(미기록)* |
| **판정** | 행·열·대각선(10선) 합 전부 검증 | 입력/문제 자체의 신뢰성 불확실 |

### 3.6 Mom Test 채점 (자가 점검)

| 항목 | 결과 |
|------|------|
| 미래 가정 없음 | 부분 충족 (증거 3 "가능성" 보완 필요) |
| 과거 행동·시간·실수 | 부분 충족 (코드 쪽 Q9·Q10 미완) |
| 진짜 문제에 솔루션名 없음 | 충족 |
| 표면/진짜 분리 | 충족 |
| 도메인(4×4, 10선, 34, 빈칸 2) | 부분 충족 → 본 보고서 §2에서 명시 |

## 5. R-G-I-O

| | 정의 |
|---|------|
| **Role** | 4×4 부분 마방진(빈칸 2개)을 손·코드로 다루는 **학습자** — 조건을 머릿속에만 두지 않고 **검증 가능한 규칙**으로 옮기는 주체 |
| **Goal** | 빈칸 2개를 채운 뒤 **10선 합이 모두 34**인지, **입력 자체가 유효한지**를 **순서대로** 판정하고, 실패 시 **어느 조건에서 깨졌는지** 말할 수 있다 |
| **Input** | `int[4][4]` — `0`(빈칸) **정확히 2개**, 나머지 `1~16` 중복 없음 |
| **Output** | ① 판정 결과 (유효 입력 / 유효 마방진 / 실패) ② 실패 시 **깨진 Rule ID** ③ *(풀이 성공 시)* `[r1,c1,n1,r2,c2,n2]` (1-index) |

## 6. 세션 3 — Rule · Command · (Skill) · Test Loop

> **주제 (한 문장):** 4×4 부분 마방진에서 10선 조건과 입력 유효성을 **무엇부터·어떤 순서로** 판정할지 명문화하여, 맞음/틀림과 실패 원인을 헷갈리지 않게 만든다.

### 6.1 성공 기준 (Mom Test 증거 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| **SC-01** | 10선·빈칸 정보를 **외우지 않아도** Rule/테스트로 추적 가능 | 증거 1 |
| **SC-02** | 풀이 전 **입력 검증 → 10선 합 검증** 순서 고정 | 증거 2 |
| **SC-03** | 타입·범위·출제 오류가 **조용히 통과하지 않음** | 증거 3 |

### 6.2 Rule

| ID | Rule |
|----|------|
| **R-01** | 격자는 **4×4**만 유효 |
| **R-02** | 빈칸(`0`)은 **정확히 2개** |
| **R-03** | `0` 제외 값은 **1~16, 중복 없음** |
| **R-04** | Magic Constant = **(1+…+16)/4 = 34**, 하드코딩 금지 |
| **R-05** | **10선** 합 = Magic Constant |
| **R-06** | **판정 순서:** R-01~03(입력) → R-05(10선) → *(이후 세션)* 풀이 |

### 6.3 Command

| ID | Command |
|----|---------|
| **C-01** | Mom Test **진짜 문제** → Rule R-01~06 번역 |
| **C-02** | Input/Output **계약** 작성 (타입·범위·실패 라벨) |
| **C-03** | R-01~03 위반 **실패 케이스 3개** (`ERR-01~03`) |
| **C-04** | R-05 **10선 검증 체크리스트** 작성 |
| **C-05** | 표면 문제(N-01~05) "하지 않음" 목록 리뷰 |

### 6.4 (Skill) — 최소 정의

| ID | Skill | 역할 |
|----|-------|------|
| **S-01** | `sum_lines(grid)` | 10선 합 목록 반환 |
| **S-02** | `find_blanks(grid)` | `0` 위치 2개 (row-major) |
| **S-03** | `label_failure(grid)` | R-01~03 **첫 위반** 라벨 |

### 6.5 Test Loop

```
[RED]   Rule → 기대 결과 1케이스 기록
  ↓
[RUN]   Command 체크리스트 / Skill로 손 계산 없이 판정
  ↓
[CHECK] SC-01~03 충족?
  ↓
[PASS/FAIL] FAIL 시 Rule ID 기록 → Command 수정 → 재RUN
```

| Loop ID | RED 케이스 | 기대 |
|---------|-----------|------|
| **TL-01** | 3×4 격자 | R-01 FAIL |
| **TL-02** | 빈칸 1개 | R-02 FAIL |
| **TL-03** | 중복 숫자 | R-03 FAIL |
| **TL-04** | 행만 34, 대각선 불일치 | R-05 FAIL |
| **TL-05** | 유효 입력, 10선 모두 34 | R-05 PASS |
